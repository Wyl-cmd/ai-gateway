## 一、SQLite 四张表

### `route_state` —— 路由健康状态（抄 freellmpool 的 lease/health/cooldown 三合一）

```sql
CREATE TABLE IF NOT EXISTS route_state (
    route_id      TEXT PRIMARY KEY,      -- "openai:key1/gpt-4o"
    provider      TEXT NOT NULL,
    account       TEXT,                  -- 账号标识（不存 key 本体，只存 key_id）
    model         TEXT NOT NULL,

    -- 健康（滚动统计）
    success_count INTEGER NOT NULL DEFAULT 0,
    fail_count    INTEGER NOT NULL DEFAULT 0,
    consecutive_fail INTEGER NOT NULL DEFAULT 0,

    -- 租约（防同一路由被并发打）
    lease_owner   TEXT,                  -- 请求 id
    lease_until   INTEGER,               -- epoch ms

    -- 冷却
    cooldown_until INTEGER NOT NULL DEFAULT 0,

    -- 配额
    quota_state   TEXT NOT NULL DEFAULT 'ok',   -- ok | exhausted
    quota_until   INTEGER NOT NULL DEFAULT 0,   -- 配额的恢复时间

    last_ok_at    INTEGER,
    last_fail_at  INTEGER,
    updated_at    INTEGER NOT NULL
);
CREATE INDEX IF NOT EXISTS idx_route_state_cool ON route_state(cooldown_until);
```

**为什么 `extended` 字段不用单独表**：一张表读写一次事务，避免「租约在 A 表、健康在 B 表」导致
并发时读到不一致状态。freellmpool 用内存字典，落盘版合成一张表。

**`account` 只存 key_id 不存 key 本体** —— 密钥在配置文件或环境变量里，DB 里只有标识符。

### `attempt_log` —— 每次破甲尝试（技术有效性记忆的原料）

```sql
CREATE TABLE IF NOT EXISTS attempt_log (
    id            INTEGER PRIMARY KEY AUTOINCREMENT,
    request_id    TEXT NOT NULL,
    model         TEXT NOT NULL,
    level         INTEGER NOT NULL,      -- 0~4
    technique     TEXT NOT NULL,         -- "rot13" / "deepinception" / "identity"
    ok            INTEGER NOT NULL,      -- 1 成功 / 0 被拒
    refusal_kind  TEXT,                  -- phrase | structure | semantic | partial
    latency_ms    INTEGER NOT NULL,
    ts            INTEGER NOT NULL
);
CREATE INDEX IF NOT EXISTS idx_attempt_model_tech ON attempt_log(model, technique);
```

**这是「模型 × 技术 成功率矩阵」的数据来源**：

```sql
SELECT model, technique,
       SUM(ok) * 1.0 / COUNT(*) AS success_rate,
       COUNT(*) AS n
FROM attempt_log
WHERE ts > ?          -- 只看近期，避免旧数据主导
GROUP BY model, technique
HAVING n >= 5         -- 样本太少不给结论
ORDER BY success_rate DESC;
```

**为什么要 `HAVING n >= 5`**：1/1 的成功率是 100% 但没有统计意义，
拿它做排序会让新技术的偶然成功误导整条策略。

### `request_log` —— 每次请求一行（成本与路由归因）

```sql
CREATE TABLE IF NOT EXISTS request_log (
    request_id    TEXT PRIMARY KEY,
    mode          TEXT NOT NULL,         -- auto | manual
    route_id      TEXT,
    model         TEXT,
    provider      TEXT,

    -- 破甲
    jailbreak_level INTEGER NOT NULL DEFAULT 0,
    jailbreak_technique TEXT,
    jailbreak_attempts INTEGER NOT NULL DEFAULT 0,

    -- 计量（只记上游 usage，不压缩）
    prompt_tokens INTEGER,          -- 上游 usage 原样记录，不做本地分词
    completion_tokens INTEGER,

    -- 结果
    ok            INTEGER NOT NULL,
    error_kind    TEXT,                  -- timeout | rate_limit | quota | upstream_5xx | refusal_all
    latency_ms    INTEGER NOT NULL,
    trace_json    TEXT,                  -- RouteTrace 的 JSON（可回放）
    ts            INTEGER NOT NULL
);
```

**`trace_json` 存完整 trace** —— 这是「route_trace 可回放」的落点：
出问题时能按原样重放一次路由决策。

### `technique_prior` —— 技术先验（可选，J5 用）

```sql
CREATE TABLE IF NOT EXISTS technique_prior (
    model       TEXT NOT NULL,
    technique   TEXT NOT NULL,
    success_rate REAL NOT NULL,
    n           INTEGER NOT NULL,
    updated_at  INTEGER NOT NULL,
    PRIMARY KEY (model, technique)
);
```

`attempt_log` 是**明细**（append-only，不删），`technique_prior` 是**聚合缓存**
（定期从明细重算）。查询走缓存，重算走明细。

## 二、配置文件（TOML）

`config.toml`（**不入 git**，`.gitignore` 已排除 `config.local.toml`、`.env`）：

```toml
[server]
host = "127.0.0.1"          # 默认只监听本地，与 C2 的教训一致
port = 8787

[storage]
db_path = "./data/gateway.db"

# ── 模式层 ──────────────────────────────────────────────
[mode]
default = "auto"            # auto | manual

[route]
# rank_targets 的四维权重（成本默认 0 = 不省钱优先）
w_health  = 0.5
w_quota   = 0.3
w_latency = 0.2
w_cost    = 0.0

# 连续失败多少次进冷却
cooldown_after_fails = 3
cooldown_seconds     = 300

# 租约时长（防并发打同一路由）
lease_seconds = 30

# ── 破甲层 ──────────────────────────────────────────────
[jailbreak]
enabled     = true          # 默认开（Master 要求）
start_level = 1             # L0 身份锚定总是先加；1 = 直接进规则型变形
max_level   = 2             # 默认到 L2；3/4 需显式开
ladder_timeout_ms = 12000   # 整条梯子的超时预算

# 只在这些情况下启用 L3（要花钱）
[l3]
enabled  = true
only_if = ["empty_response", "hard_refusal"]   # 纯空响应或硬拒绝才升级

[l4]
enabled       = false       # PAIR/TAP 默认关闭
budget_ms     = 30000
max_attempts  = 8

[refusal]
head_chars   = 200          # 只看响应头 200 字符（KXNS 定的）
extra_phrases = []          # 用户可补短语

# ── 接入层鉴权 ──────────────────────────────────────────
[auth]
# 客户端用的网关令牌（不是上游 key）。留空 = 不鉴权（仅 127.0.0.1 安全）
gateway_keys = []

# ── 上游 provider ───────────────────────────────────────
[[providers]]
name    = "deepseek"
kind    = "openai"          # 复用 openai 协议
base_url = "https://api.deepseek.com/v1"
enabled = true

  [[providers.accounts]]
  key_id = "ds-main"        # 只是标识，真 key 从环境变量读
  key_env = "DEEPSEEK_API_KEY"
  quota  = "unlimited"

[[providers]]
name    = "openai"
kind    = "openai"
base_url = "https://api.openai.com/v1"
enabled = false

  [[providers.accounts]]
  key_id = "oa-1"
  key_env = "OPENAI_API_KEY_1"

[[providers]]
name    = "anthropic"
kind    = "anthropic"
base_url = "https://api.anthropic.com"
enabled = false

[[providers]]
name    = "gemini"
kind    = "gemini"
base_url = "https://generativelanguage.googleapis.com"
enabled = false

[[providers]]
name    = "aggregator"      # 国内聚合（如 one-api 自己搭的）
kind    = "openai"
base_url = "http://127.0.0.1:3000/v1"
enabled = false
```

**关键设计**：

| 设计 | 理由 |
|---|---|
| `host = "127.0.0.1"` 默认 | 与 C2 那次教训一致：默认只监听本地，要暴露必须显式改 |
| `key_env` 而非 `key` | 密钥只在环境变量里，配置文件可以安全备份/分享 |
| `[[providers.accounts]]` 数组 | 多账号天然支持（配额耗尽换号） |
| `w_cost = 0.0` 默认 | 不偷偷省钱，要省钱必须显式开 |
| `max_level = 2` 默认 | L3 要花钱、L4 很慢，默认不碰 |

## 三、API 契约

### `POST /v1/chat/completions`（OpenAI 兼容）

**请求**（标准 OpenAI 格式 + 五个私有头）：

```http
POST /v1/chat/completions
Authorization: Bearer <gateway_key>
Content-Type: application/json
X-Gateway-Mode: auto
X-Gateway-Route: openai/gpt-4o          (仅 manual 模式)
X-Gateway-Fallback: strict
X-Gateway-Jailbreak: auto

{"model":"gpt-4o","messages":[{"role":"user","content":"..."}],"stream":false}
```

**响应头（每次都有，不许静默）**：

```http
X-Gateway-Request-Id: req_01H...
X-Gateway-Route: deepseek/deepseek-chat
X-Gateway-Mode: auto
X-Gateway-Jailbreak-Trace: L1:rot13:2        # 级别:技术:第几次成功
X-Gateway-Levels-Tried: identity,rot13,base64
```

**`X-Gateway-Jailbreak-Trace` 格式**：`L<级别>:<技术>:<第几次尝试成功>`
- `L0:identity:1` —— 身份锚定一次就过（最常见）
- `L1:rot13:2` —— 身份锚定被拒，第 2 次用 rot13 成功
- `none` —— 全部失败（此时 HTTP 200 但内容是最后一次的响应，带 `X-Gateway-Jailbreak-Trace: none`）

### 错误码

| HTTP | `error.type` | 何时 |
|---|---|---|
| 401 | `invalid_api_key` | 网关 key 缺失/错 |
| 400 | `invalid_route` | `X-Gateway-Route` 格式错 |
| 404 | `model_not_found` | 所有 provider 都不支持该 model |
| 429 | `quota_exhausted` | 所有账号配额耗尽 |
| 502 | `upstream_error` | 上游 5xx |
| 503 | `no_healthy_route` | `strict` 模式下目标全挂 |
| 504 | `jailbreak_timeout` | 梯子超时 |

**错误体沿用 OpenAI 格式**（客户端不用改）：

```json
{"error": {"type": "no_healthy_route", "message": "openai 所有账号不可用，且 fallback=strict"}}
```

### `POST /v1/messages`（Anthropic 兼容）

同一套内部链路，只是入口格式不同（`system` 是顶层字段、`messages` 里 user/assistant 交替）。
转发给 anthropic 类 provider 时格式不变；转发给 openai 类 provider 时在 G2 里转换。

### `GET /v1/models`

列出「至少一个启用 provider 支持」的模型（查能力表，不是写死列表）。

### `GET /healthz`

```json
{"ok": true, "routes": 12, "healthy": 10, "cooldown": 2, "db": "wal"}
```

## 四、能力表（`ability`）

抄 one-api `model/ability.go`：一条记录 = 「某 provider 的某账号能服务某模型」。

```python
@dataclass(frozen=True)
class Ability:
    provider: str
    account: str
    model: str
    priority: int          # 越小越优先
```

**在内存里建索引**：`dict[model, list[Ability]]`，路由时按模型反查候选集。
**不从 DB 查** —— 这张表是静态配置派生的，配置加载时建好索引即可。

## 五、数据流向

```
请求
  ↓
[G8 接入] 鉴权 → 解析 5 个私有头
  ↓
[G4 破甲 J4] 无（这里还没响应可检测）
  ↓
[G7 模式] auto: 候选集来自能力表 → G3 rank_targets
           manual: 锁 provider / account
  ↓
[G3 路由] 租约 → 选中一个 route_id
  ↓
[G2 转发] 调上游 → 拿响应
  ↓
[G4 破甲 J4] 检测拒绝？
    ├─ 是 → 记 attempt_log(ok=0) → 升级到下一级技术 → 回到 [G4 破甲 J1]
    └─ 否 → 记 attempt_log(ok=1) → 继续
  ↓
[G6 可观测] 写 request_log（含 trace_json）
  ↓
返回响应 + 5 个响应头
```

**重试路径不回退到 G7** —— 破甲重试沿用第一次选中的路由，
否则「换个技术又换个模型」会让归因失效（不知道是技术起效还是模型起效）。
