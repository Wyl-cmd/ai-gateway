# 落地总表 —— 施工顺序（按父先子后）

> **铁律**：每批走四道门 —— ① 方案（本节六要素）→ ② 测试必红（`AssertionError`/`KeyError`，
> 不是 `NameError`）→ ③ 最小改动转绿 → ④ 全量回归。
>
> **父→子判据**：A 是 B 的父 ⟺ **B 做完立刻跑一遍必须依赖 A 已成立**。
> 不是按章节顺序，不是按域。

### J5 落地记录

| 项 | 内容 |
|---|---|
| 门③ | 17 passed（修 1 条测试索引后） |
| 门④ | 229 passed / exit=0 |

**这一层解决的是「冷启动悖论」**：25 技术 × 5 样本 = 125 次失败请求才建得起矩阵，
低频用户永远建不起来，于是永远从头试。两条腿走：
```
内置先验（技术大类硬编码顺序）  ← 零样本时用
随用随学（n >= 5 才覆盖先验）  ← 攒够样本后接管
```

**三种位置**（不能只按 rate 排）：
```
学到的（rate > 0）  按 rate DESC, n DESC   → 最前
没学到的            按先验顺序             → 中间
学过但全失败        rate == 0              → 最后
```
「全失败」必须单独一档：rate=0 和「没样本」数学上都是 0，但含义相反 ——
一个是「试过，不行」，一个是「没试过」。

**不导公开评估数据**。EasyJailbreak / garak 有现成结果，但分布完全不同
（GPT-4/Claude-2 时代模型、几乎全英文语料、特定有害 seed）。
导入别人的先验比不用更危险 —— 会把排序锚死在错误分布上，
而且极难发现（「有数据支撑」看起来比「拍脑袋」可信）。

**接线是重点**（否则 J5 就是死代码）：
- `_jailbreak_text` 优先用 `memory.rank()`，失败才退回 `select_techniques`
- 每次尝试（成功和拒绝**都**）写进 `attempt_log` —— 只记成功会让
  「哪些技术对这个模型无效」永远学不到
- 记忆写失败不能影响主链路（`try/except pass`）

**门③ 撞到的核心问题：三处映射不是双射，可逆性直接崩**

可逆性不是「顺手验证一下」，它是**编码类技术的存在前提**：模型解不出来的编码等于噪声，
白烧一次升级机会还可能让「技术有效性记忆」学出错误的成功率。

1. **`self_define_cipher` 映射表撞车**。第一版让每个字符独立哈希取字母，
   `l` 和 `l` 都映射到 `l`，`hello world` → `rdlloworld` —— 两个 `l` 还原不出来，
   空格也丢了（空格不在表里，解码时找不回位置）。
   改成「按 `sha256(seed+c)` 排序 a-z」生成一个**排列**，天然双射。
2. **`leetspeak` 的 `l→1` 和 `i→1` 撞车**。反查时 `1` 只能还成 `l`，`elite` → `ellte`。
   去掉 `l→1`，只保留 a/e/i/o/s/t/g 这一族唯一映射。
3. **`decode` 没剥离提示语**。`transform` 输出是「提示语：密文」，
   6 个 decode 直接对整串操作，把提示语里的中文也当密文处理了。
   加 `_strip_hint()` 按最后一个「：」切开。

**测试口径也修了一条**：`rot13`/`reverse`/`caesar` 原来用**外部解码器**验可逆
（`codecs.decode` / `enc[::-1]` / 手工移位），但外部解码器处理不了带提示的输出。
这不是实现的错 —— 提示语是模板层的事、编码器该只输出密文。统一改成用 `t.decode()` 验。

**门③ 撞到的 4 个真问题（都是实现参数，不是测试口径）**：

1. **`_L3_MIN_LEN` 定 200 太大**。中文 200 字 ≈ 英文 400 词，而「三百字伦理说教」
   这类典型空转只有 150 字左右 → 漏判。改成 **120**（中文信息密度高，同样语义
   用的字数比英文少）。
2. **partial 判定用长度是错的**。第一版 `len > 200` 才算 partial，结果
   `"I can't give you a full exploit, but here's the general idea..."` 只有 108 字符,
   明明后面给了内容却判成全拒。改成 **转折词（but here / 但是 / 不过）+ 实质内容**。
   长度和「有没有答东西」根本不是一回事 —— 短而有用比长而空洞好。
3. **极短道歉漏判**。`"抱歉。"` 不命中任何短语（库里都是「抱歉，我不能…」这种
   带宾语的完整句）→ 加「≤20 字符 + 含道歉词」兜底。
4. **短语库漏了「拒给」这一族**。`i can't give / share / reveal / show` —— 拒绝语
   后面接动词原形的变体，原来只有 `help with / provide / assist with` 这类。

**一个设计上的额外发现**：`test_提到拒绝词但不是在拒绝`（"我遇到过一个拒绝服务的攻击"）
这条守住了短语库不收单字「拒绝」的底线。如果为了覆盖率把单字塞进去，正常回答会被
大面积误判 —— 误判的代价是破甲层无脑升级，白烧 token 还可能把好答案改坏。

   唯一区别是「左边这个名字认不认识」。加 `DEFAULT_PROVIDERS`（44 个主流 provider 名）
   才解得开。靠硬编码「斜杠左边是 provider」会让 OpenRouter / Together 那类
   `组织/模型` 命名的上游全解析错。

2. **目标可用时不该追加备选**。第一版写成「目标能用也把备选都塞进队列」，
   结果 `openai/gpt-4o` 明明能走，队列里还挂着 azure 和 deepseek-chat。
   队列一长，上层重试时第一次失败就可能滑到跨型号上去，provider 锁形同虚设。
   **降级的定义就是「目标不行才降」**。

**关键设计：重试的两层结构**
```
外层：候选队列（换账号 / 换家 / 换型号）—— G7 决定队列里有什么
内层：破甲阶梯（L0 → L1 → L2 …）    —— G4 决定每级怎么变形
```
顺序：**先在同一账号上把破甲试完，再换账号**。因为换账号换的是「额度」不换「能力」，
同一个模型换个 key 审查策略一模一样。但**上游 5xx 要直接换账号**，
provider 挂了变形一百次也还是 404。

**接入层不做任何自己的判断**。它只接线 —— 一旦开始「顺手也判一下」，
就成了第二个决策点，和 G3/G4 必然不一致，「为什么走了这条路」再也说不清。

**门③ 撞到的坑**：`test_配额耗尽会换号` 变红，我第一反应是换号逻辑坏了，
实际是**测试桩写错** —— `calls.append` 写在 `responder` 之后，而 responder 会 raise，
导致 `len(calls)` 永远是 0，每次都走「第一次」分支。
**桩的问题会伪装成实现的问题**，加打印一看就清楚。

### G8 真跑验证（2026-11-12）

启动 `.venv/bin/python -m gateway.demo` 后用真实 HTTP 打，抓出 **2 个单元测试没覆盖的 bug**：

| # | 现象 | 根因 | 修法 |
|---|---|---|---|
| 1 | 正常请求 500 | `X-Gateway-Trace-Json` 用 `ensure_ascii=False`，中文进 HTTP 头 → `UnicodeEncodeError: 'latin-1' codec can't encode` | 加 `to_json_header()`（`ensure_ascii=True`）+ `_ascii_safe()` 兜 `header_value()`/`warning()` |
| 2 | **请求 gpt-4o 返回 deepseek-chat** | `rank_targets` 不知道用户要什么型号。三个候选同分按 key 字典序排到 deepseek 第一 → auto 直接跳到三层降级的**第三层（跨型号）**，而这一层本该默认关闭 | `ModeRouter.plan` 加 `prefer_model`，auto 先在同型号里排，同型号全挂才看 policy 决定跨不跨 |

**这两个 bug 的共同点：单元测试全绿，真跑才暴露。**
- bug 1 是因为测试里的 trace 内容恰好都是 ASCII
- bug 2 是因为测试桩的候选恰好只有一个型号，没得选
**「能通过的测试」不等于「能用的服务」** —— 这就是 G10 端到端必须存在的理由。

修完实测：
```
请求 gpt-4o        → actual=gpt-4o;        provider=openai     无降级告警
请求 deepseek-chat → actual=deepseek-chat; provider=deepseek
请求不存在的型号    → 503「strict 不跨型号」
```

**不用 rich**。NG 那次 `console.print(text)` 没关 markup，靶场返回带 `[/xxx]`
导致 MarkupError、**整份报告丢失还表现成任务失败**。这里的结论不是「记得加
markup=False」，而是：自用工具的表格不值得为它引一个能把输出炸掉的依赖。
纯 print + 手工对齐就够。

**编码兜底**：CI 里 locale 常是 C/POSIX（`PYTHONIOENCODING=ascii`），
直接 print 中文会 UnicodeEncodeError。`_out()` 统一转义兜底，不崩。

**退出码契约**：`--help`→0 / 不带参数→0（给帮助不报错）/ 未知子命令→2 / 子命令 `--help`→0。
