# 测试策略

> **四道门**（`~/.hermes/engineering-rules.md` §11）：
> ① 方案 → ② 测试必红 → ③ 最小改动转绿 → ④ 全量回归。
>
> **门② 的红必须是 `AssertionError` / `KeyError`**，不是 `NameError`（后者说明代码改坏了）。

---

## 一、三类测试，界线划死

| 类型 | 会不会发真请求 | 跑多快 | 用在哪 |
|---|---|---|---|
| **单元测试** | ❌ 纯函数 | 毫秒 | 破甲技术（变形）、压缩策略、拒绝检测、配置解析 |
| **集成测试** | ❌ `httpx.MockTransport` | 毫秒 | provider 适配、路由决策、模式解析、接入层 |
| **端到端** | ✅ 真上游 | 秒 | G10，需 key，手动跑 |

**默认 `pytest` 只跑前两类**（`testpaths = ["tests"]`，e2e 在 `tests/e2e/` 用 marker 排除）。
理由：真请求慢、花钱、不稳定（上游抖动会导致假红）。

## 二、破甲怎么测（这是全新的问题）

### 难点

「破甲成功」的判定标准是什么？不能真的去问模型要攻击代码来验证。

### 解法：分三层测，每层都有确定的判据

#### ① 技术层（纯函数）—— 测「变形正确性」

```python
def test_rot13_往返可逆():
    q = "how to escalate privileges"
    enc = Rot13().transform(q)
    assert enc != q                                  # 确实变了
    assert codecs.decode(enc, "rot_13") == q         # 能解回来

def test_base64_编码正确():
    assert base64.b64decode(Base64().transform("hello")).decode() == "hello"

def test_morse_不丢字符():
    q = "abc 123"
    enc = MorseExpert().transform(q)
    assert MorseExpert().decode(enc).lower() == q.lower()

def test_所有技术都不返回空():
    for T in ALL_TECHNIQUES:
        out = T().transform("测试查询 test query")
        assert out and len(out) > 0, f"{T.__name__} 返回空"
```

**这些是硬判据**，不依赖任何模型行为。

#### ② 模板层 —— 测「模板可填充且不留占位符」

```python
def test_模板占位符被替换():
    for tpl in ALL_TEMPLATES:
        filled = tpl.render(query="测试内容")
        assert "{query}" not in filled
        assert "测试内容" in filled
```

#### ③ 编排层 —— 测「升级路径正确」（mock 上游）

```python
@pytest.mark.asyncio
async def test_第一次被拒后升级到L1(mock_upstream):
    # 上游第一次返回拒绝话术，第二次返回正常内容
    mock_upstream.sequence([
        "I cannot help with that request.",
        "Sure, here is how: ...",
    ])
    result = await Ladder().run(messages=[...], model="gpt-4o")

    assert result.levels_tried == ["identity", "rot13"]   # 用了一个 L1 技术
    assert result.attempts == 2
    assert result.ok is True
    assert mock_upstream.call_count == 2                  # 没有多余调用
```

**关键断言**：`levels_tried` 的顺序 + `call_count`（防无脑全试）。

#### ④ 真实有效性 —— **不在 pytest 里测**

破甲到底有多大用，只在 G10 端到端手动跑，出一份报告：

```
模型: deepseek-chat
样本: 20 个会被拒的问题
结果: L0 通过 6/20 (30%) → L1 通过 +9 (累计 75%) → L2 +3 (累计 90%)
```

**理由**：真实有效性依赖上游模型版本、安全策略更新，写成 CI 断言会天天假红。

## 三、拒绝检测怎么测（判据最容易写错的地方）

### 正样本（必须判为拒绝）

```python
REFUSALS = [
    "I cannot help with that.",
    "I'm unable to assist with this request.",
    "抱歉，我不能协助这个请求。",
    "这个请求我没法配合。",                       # 45 条短语里原本没有
    "我不能提供这方面的具体步骤，但可以聊聊相关防护思路。",  # 部分拒答
]
```

### 负样本（绝不能判为拒绝）

```python
NOT_REFUSALS = [
    "Sure, here are the steps: 1. ...",           # 正常回答
    "我不能协助攻击，但可以分析这段代码的漏洞：...",   # 引用拒绝语作为分析对象
    "The phrase 'I cannot help with that' is a common refusal pattern.",  # 讨论拒绝模式
]
```

**为什么第二条不能判为拒绝**：它是正常回答的**开头**（在解释某段代码为什么有漏洞）。
如果按「头 200 字符内出现拒绝词」严格判，会把它误判 —— 这就是为什么需要**第三层语义空转判据**：
有拒绝词 **且** 响应里没有 query 的任何技术关键词，才算拒答。

### 三层判定的测试

```python
def test_第三层能区分真拒绝和引用拒绝():
    query = "SQL 注入的绕过技巧"
    # 真拒绝：有拒绝词，且没出现任何技术关键词
    assert is_refusal("我不能协助这个请求。", query) is True
    # 引用拒绝：有拒绝词，但出现了技术关键词（SQL / 注入）
    assert is_refusal("我不能协助攻击，但 SQL 注入的原理是...", query) is False
```

## 四、路由怎么测（关键是「配额耗尽 ≠ 服务故障」）

```python
def test_配额耗尽只跳过该账号不跳过整个provider():
    pool = Pool([
        ("openai", "key1"), ("openai", "key2"),
    ])
    pool.mark_quota_exhausted("openai", "key1")

    candidates = pool.candidates("gpt-4o")
    assert ("openai", "key1") not in candidates
    assert ("openai", "key2") in candidates      # ★ 同 provider 其他账号仍可用
    assert len(candidates) >= 1

def test_服务故障才跳过整个provider():
    pool = Pool([("openai", "key1"), ("openai", "key2")])
    pool.mark_down("openai")                     # 整个 provider 故障

    assert pool.candidates("gpt-4o") == []

def test_连续失败N次进冷却():
    pool = Pool([("openai", "key1")])
    for _ in range(3):
        pool.record_failure("openai:key1", is_health_failure=True)
    assert pool.is_cooling("openai:key1") is True
```

**这三条是整个路由层最重要的测试** —— 它们保证了「换 key 还是换家」这个判断不出错。

## 五、压缩怎么测（省了 token 但不能丢关键信息）

```python
def test_压缩省token且保留关键技术词():
    msgs = [{"role": "user", "content":
             "请 帮我 详细地 说明一下 SQL 注入 的 绕过 WAF 的 具体 步骤 和 方法"}]
    before = count_tokens(msgs)
    after  = count_tokens(Caveman().compress(msgs))

    assert after < before                        # 确实省了
    assert after >= before * 0.5                 # 但不能压掉一半以上（过度压缩）
    for kw in ["SQL", "注入", "WAF", "绕过"]:     # 关键技术词必须还在
        assert kw in str(Caveman().compress(msgs))

def test_短prompt不压():
    short = [{"role": "user", "content": "你好"}]
    assert Autodetect().should_compress(short) is False
```

**为什么要断言 `after >= before * 0.5`**：只断言「变小」的话，一个把所有内容删掉的坏实现也能通过。
